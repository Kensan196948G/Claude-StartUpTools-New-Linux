# 影響分析とロールバック: エージェントの指示書を R0 から R2 へ（PR #237、R4）

状態: 2026-11-25。PR #237 の R4 要件（変更影響分析・ロールバック手順）を満たすための文書。

## 1. 変更内容

`config/ship-policy.json` の `risk.rules` に、R3 と R1 の間へ R2 の規則を 1 つ追加する。規則は先頭から評価されるため、R0（`**/*.md`）・R1 より先に当たる。

対象パターン: `CLAUDE.md`、`**/CLAUDE.md`、`AGENTS.md`、`**/AGENTS.md`、`**/SKILL.md`、`.claude/**`、`Claude/templates/**`、`.agents/**`、`Codex/templates/**`

## 2. 影響分析

### 2.1 分類の変化（追跡ファイル全件、2026-11-25 実測）

| | R0 | R1 | R2 | R3 | R4 |
| --- | --- | --- | --- | --- | --- |
| 変更前 | 661 | 117 | 284 | 16 | 73 |
| 変更後 | 88 | 115 | 859 | 16 | 73 |

- R0→R2: 573 件（エージェントの指示書）
- R1→R2: 2 件（`.claude/claudeos/tests/lib/utils.test.js`、`Claude/templates/claudeos/tests/lib/utils.test.js`。エージェントの環境に配布されるテスト）
- R3・R4 は変化なし。上位規則（`.claude/settings.json`=R4、`**/hooks/**`=R4 など）は先に評価されるため優先されたまま

### 2.2 運用への影響

| 対象 | 影響 |
| --- | --- |
| 指示書を変える PR | R2 になる。R2 の要件はロールバック手順（`--rollback-doc`）。Ship レビュー（`/ship` と署名）は R2 で必須（今と同じ: 現状でも R0 で Ship 署名が実質必須） |
| 通常の文書だけの PR（README・CHANGELOG・`docs/**`・`reports/**`） | 変化なし（R0 のまま） |
| 後続 PR #238（R0・R1 の human-diff） | この変更が前提。指示書を含む PR では human-diff が使えなくなる（意図どおり） |
| マージ判定・承認・ruleset | 変化なし |
| gate の判定ロジック・コード | 変化なし（設定値のみ） |

### 2.3 効く時期

gate は main 上のポリシー（`loadTrustedPolicy`）を使うため、この PR のマージ後に作られる gate から新しい分類が使われる。マージ前に作られた gate の記録は変わらない。

### 2.4 リスク

- 誤って広く当たる: `.claude/**` には `.claude/claudeos/data/*.json`（学習データ）も含まれ、R2 になる。学習データだけの PR は通常作らないため影響は小さい。過剰側（安全側）の誤分類
- 当たり漏れ: 上の 9 パターン以外の指示書（例: 別名の手順書）は R0 のまま。見つけ次第パターンを追加する

## 3. ロールバック手順

1. この PR を `git revert` する PR を作る（変更は `config/ship-policy.json` の 1 ブロックとテストのみ）
2. revert PR も R4 なので、いつもどおり品質検証 → `/ship` → 署名 → 品質判定 → 承認 → マージ
3. マージ後、`node -e` で `CLAUDE.md` が R0 に戻ることを確認する
4. 後続の PR #238 がマージ済みの場合は、先に #238 を戻すか、指示書が R0 に戻ると human-diff の対象になる点を受け入れるかを判断する（#238 を残したままの revert は推奨しない）

データの移行・削除は無い。設定値を戻すだけで元の分類に戻る。
