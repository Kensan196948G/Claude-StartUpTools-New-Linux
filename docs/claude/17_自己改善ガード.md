# 17. 再帰的自己改善ガード

DeepMind「From AGI to ASI」が論じる「再帰的自己改善（Recursive Self-Improvement）」は強力だが、
制御なく適用すると暴走リスクがある。ClaudeOS では既存の安全境界を根拠込みで形式化し、
**「改善してよい範囲」と「人間承認が必要な範囲」を明確に分ける**。

## 基本原則

```text
AI は提案する。人間は承認する。システムは記録する。
```

改善ループ（`/learn` → `/evolve` → `/eval`）は
「実行回数を増やすほど賢くなる」ではなく、
「失敗パターンを蓄積し、次の失敗を減らす」に留める。

## 自律改善 OK 領域

ClaudeOS が人間承認なく実行してよい改善作業。

| 区分 | 具体例 |
|---|---|
| ドキュメント追記 | docs/ への補足追加・誤記修正 |
| テスト追加 | 既存カバレッジを下げない範囲の新規テスト |
| Lint 修正 | 自動整形・命名 lint 指摘の修正 |
| 小規模リファクタ | 関数 ≤ 50 行・影響範囲が 1 ファイル内 |
| 失敗パターン記録 | `state.json.learning.failure_patterns` への書き込み |
| Agent 評価ログ追記 | `state.json.metrics.agent_scorecard` の更新 |
| 改善提案の起票 | GitHub Issue の Draft 作成（実行は人間） |

## 人間承認が必要な領域

以下は必ず「人間の明示的な選択」を待つ。

| 区分 | 根拠 |
|---|---|
| `CLAUDE.md` 中核方針の変更 | 全プロジェクトに波及するため |
| `settings.json` Hooks の無効化 | 安全弁を外す操作のため |
| 権限設定の緩和（`allowedTools` 追加） | 攻撃面が広がるため |
| main/master への直接 push | CLAUDE.md §Git ルール |
| Secrets / 課金 / 外部サービス設定 | 不可逆・費用発生のため |
| Supervisor の全プロジェクト適用 | 意図しない広範な副作用のため |
| Security Critical 指摘が残る PR の merge | CI 安全弁として機能するため |
| 本番デプロイ・本番公開 | CLAUDE.md §CTO 自律開発境界 |

## 禁止事項（絶対遵守）

- `--no-verify` でフックをスキップしない
- `git push --force` を承認なく実行しない
- 同一エラー 3 回到達時に「もう 1 回試す」を繰り返さない
- `/evolve` の結果を人間レビューなく main に merge しない
- AI が AI の権限を拡大する（self-grant）操作は行わない

## 改善ループのガードチェックリスト

`/learn`・`/evolve`・`/eval` 実行前に確認する項目。

```text
[ ] 改善対象は「自律改善 OK 領域」内か？
[ ] 影響範囲は局所的か（1 ファイル or 1 モジュール以内）？
[ ] CI が現在 success 状態か？
[ ] 同一エラー再発回数は 2 以下か？
[ ] Security Critical 指摘は 0 か？
[ ] 改善後に test / lint / build が通るか？
[ ] 変更を feature branch + PR 経由で提出するか？
```

1 項目でも NO なら改善を停止し、人間に判断を委ねる Issue を起票する。

## 安全な自己改善サイクル

```
/learn              → 失敗パターン・成功パターンを state.json に記録
/evolve             → instincts をクラスタリングして skill 候補を生成（PR で提案のみ）
/eval               → 変更結果を採点し state.json.metrics.improvement_adoption_rate を更新
/measure            → KPI スナップショットを取得し改善前後を比較
```

自己改善がコードに反映されるのは、PR → review → STABLE 判定 → 人間 merge の後のみ。

## 6 つの壁への対応

DeepMind 論文が挙げる ASI への障壁を ClaudeOS 運用に翻訳する。

| 障壁 | ClaudeOS での対応 |
|---|---|
| データの壁 | `/prune` で陳腐化コマンド・Agent を定期整理 |
| 計算資源の壁 | `effort_strategy` でフェーズ別 effort を調整 |
| 物理世界の壁 | CI 実行時間・cron 間隔を現実の制約として受け入れる |
| 抽象化の壁 | `/instinct-export` で直感を外部化・客観視する |
| 集団調整の壁 | Agent Scorecard で偏り検出・役割再分配 |
| 原理的限界の壁 | AI を「全知全能」と扱わず、人間判断を残す |
