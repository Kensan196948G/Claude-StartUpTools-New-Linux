# 16. AI 組織設計

Google DeepMind「From AGI to ASI」が示す「超知能は単体の脳ではなく組織として現れる」という視点を
ClaudeOS の Agent Teams 運用に適用した設計ドキュメント。

## 基本思想

従来の「1 つの AI にタスクを投げる」モデルから、
**複数 AI エージェントが分業・連携し、全体として高い知能を発揮する「AI 開発組織」** へ移行する。

ClaudeOS は「Claude を起動するツール」ではなく、**AI 開発部門を起動・監視・評価するプラットフォーム** として位置づける。

## 組織階層

```
Human Owner
  └─ 最終判断（main merge / 本番公開 / Secrets / 破壊的変更）
       │
       ▼
  CTO Claude
  └─ 全技術判断・優先順位・実行方針
       │
       ▼
  Supervisor / cron
  └─ セッション管理・タイムアウト・再起動制御
       │
       ▼
  Workflow Engine
  └─ Agent Teams の起動・並列実行・結果集約
       │
       ├─ Development Team
       │    architect / api-designer / dev-api / dev-ui
       │    build-error-resolver / <lang>-build-resolver
       │
       ├─ Quality Team
       │    qa / tester / e2e-runner / tdd-guide
       │    <lang>-reviewer / code-reviewer / performance-reviewer
       │
       ├─ Security / Audit Team
       │    security-reviewer / audit-agent / cmdb-agent
       │
       ├─ Operations Team
       │    ops / ci-manager / release-manager
       │    incident-triager / harness-optimizer
       │
       ├─ Learning Team
       │    refactor-cleaner / outcome-grader / doc-updater / docs-lookup
       │
       └─ Management Team
            orchestrator / cto / chief-of-staff / manager / planner / loop-operator
       │
       ▼
  Hooks / CI / Metrics
  └─ PostToolUse / PostCompact / 通知 / state.json 更新 / ONBOARDING 再生成
```

## Agent Scorecard（組織評価）

同じモデルをコピーした AI を並べるだけでは多様性が生まれない。
Agent Teams は **役割・評価軸・入力データ・判断ルール** を意図的に分けることで集団知能を高める。

各 Agent の成果を `state.json.metrics.agent_scorecard` に蓄積する。

```json
"agent_scorecard": {
  "qa": {
    "tasks_assigned": 0,
    "tasks_succeeded": 0,
    "bugs_detected": 0,
    "false_positive": 0
  },
  "security-reviewer": {
    "tasks_assigned": 0,
    "tasks_succeeded": 0,
    "critical_findings": 0,
    "false_positive": 0
  },
  "architect": {
    "tasks_assigned": 0,
    "tasks_succeeded": 0,
    "design_accepted": 0,
    "reverted": 0
  }
}
```

## AI 組織 vs 人間組織の対応

| 人間組織 | ClaudeOS AI 組織 |
|---|---|
| 経営層 | Human Owner |
| CTO | CTO Claude |
| 管理職 | orchestrator / chief-of-staff / manager |
| 専門部門 | Agent Teams（開発・品質・セキュリティ・運用・学習） |
| 稟議・承認フロー | Human Final Decision Boundary |
| 社内評価制度 | Agent Scorecard |
| 内部監査 | audit-agent / security-reviewer |
| 事後検証 | CI / Hooks / STABLE 判定 |
| 市場フィードバック | GitHub Issues / CodeRabbit / Codex review |

## 多様性の担保

同質エージェントを大量に並べても相乗効果は弱い（DeepMind 論文 §集団調整の壁）。
ClaudeOS では次の多様性を設計に組み込む。

1. **役割分離**: 実装・レビュー・品質・セキュリティは別 Agent が担当
2. **独立評価**: Codex review と CodeRabbit は独立した外部視点として維持
3. **対抗レビュー**: 認証/DB スキーマ変更時は `/codex:adversarial-review` 必須
4. **Devil's Advocate**: 設計フェーズでパターン C（設計検討）を活用

## 人間の役割

DeepMind 論文「人間の遅さが強みかもしれない」より:
AI は高速だが、人間は **熟慮・責任・社会的合意・倫理的ブレーキ** を担える。

ClaudeOS は「AI が走り、人間が信号機になる」設計を維持する。

| AI が担当 | 人間が担当 |
|---|---|
| 実装・テスト・レビュー | main merge の最終承認 |
| PR 作成・CI 実行 | 本番公開の最終承認 |
| ドキュメント更新 | Secrets / 課金 / 外部サービス設定 |
| 失敗パターン記録 | Supervisor 全プロジェクト適用 |
| 改善提案の立案 | 破壊的削除・不可逆変更 |
