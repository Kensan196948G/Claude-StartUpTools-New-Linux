# 使い方

## メニュー

```bash
./start.sh
```

主な操作:

| キー | 内容 |
|---|---|
| `L1` | 選択プロジェクトをフォアグラウンド起動 |
| `T1` | 選択プロジェクトを 4役割一括起動（tmux 4分割: cto / backend / frontend / qa。役割別 `--name` + worktree 自動作成。CTO ペインへ `TEAM_START_PROMPT.md` を初期プロンプト自動注入。詳細は docs/claude/19 §3） |
| `S1` | 選択プロジェクトをバックグラウンド自律起動 |
| `MO` | 監視と Supervisor 操作 |
| `15` | セッション状態監視 |

## 起動時の自動処理

全起動経路（L / S / cron / T。チーム worktree 含む）は起動前に
`lib/template-sync.sh` がテンプレート配布と settings.json の自動修復を行います。

- テンプレート配布: `START_PROMPT.md`（毎回上書き）、`TEAM_START_PROMPT.md` /
  `CLAUDE.md` / commands / skills（存在しない場合のみ）、`.coderabbit.yaml`（差分時のみ）
- settings.json sanitize（autocompact thrashing 恒久対策）:
  旧 env `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` の除去と、SessionStart matcher `*` の
  コンテキスト注入 hook（session-start.js 等）を `startup|resume|clear` へ正規化。
  修復時のみ原本を `settings.json.bak-autocompact-fix` へ退避します（初回のみ・冪等）。
  実体は `scripts/setup/sanitize-settings.js`（init 時の merge とロジック共有）。
  修復失敗時も起動は継続します（fail-soft）。

## Supervisor

個別適用:

```bash
bash bin/autonomy.sh start --project CivilPDF-DX
```

全適用の確認:

```bash
bash bin/autonomy.sh start --all --dry-run
```

全適用の実行:

```bash
bash bin/autonomy.sh start --all --yes
```

停止:

```bash
bash bin/autonomy.sh stop --project CivilPDF-DX
bash bin/autonomy.sh stop --all --yes
```

## セッション状態監視

```bash
bash libexec/watch-session.sh
```

実行中の `claudeos-*` セッションを一覧し、接続・停止を行います（メニュー項15）。
Supervisor の全適用は `bash bin/autonomy.sh start --all --dry-run`（確認後 `--yes`）を使います。
