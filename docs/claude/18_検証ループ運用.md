# 18. 検証ループ運用 🔁

Anthropic 公式ブログ
[Building verification loops in Claude Code with skills](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills)
(2026-07-22) を本ツールと登録プロジェクトへ適用した運用の正本。

## 18.1 検証ループとは

AI エージェントが自分の作業をチェック（テスト・lint・カスタムチェック実行）し、
失敗を修正してから先へ進む反復サイクル。Claude Code ではスキル
（`.claude/skills/<name>/SKILL.md`）としてパッケージ化することで、
人間の記憶に頼らず全セッションで同じチェックが適用される。

### スキル自動発見の条件（重要）

- **`<name>/SKILL.md` のディレクトリ形式 + YAML frontmatter（name / description）が必須**
- flat な `.claude/skills/<name>.md` は**認識されない**
  （2026-07-24 に本リポジトリで実証: flat 形式の 2 スキルはスキル一覧に不在、
  ディレクトリ形式へ移行した直後に一覧へ出現）

## 18.2 本リポジトリのスキル構成

| スキル | 形態 | 用途 |
|---|---|---|
| `/verify-startuptools` | standalone / embedded | bash 構文・bats/node テスト・テンプレート整合性・正本/テンプレ同期・secret 確認の検証ループ |
| `/cto-session-start` | standalone | CTO セッション開始手順（Build 後に verify-startuptools を embedded 呼び出し） |
| `/webui-health-check` | standalone / chained | Mission Control WebUI の健全性確認 → 修正 → 再確認 |

## 18.3 登録プロジェクトへの配布

`lib/template-sync.sh` がプロジェクト起動前に starter スキルを配布する。

- 正本: `Claude/templates/claude/skills/<name>/SKILL.md`
- 配布先: `<project>/.claude/skills/<name>/SKILL.md`
- **存在しない場合のみ配布**（プロジェクト側カスタマイズを保護・上書きしない）
- 現在の配布対象: `verify-app`（lint → typecheck → test → build の汎用検証ループ）
- 追加手順は `Claude/templates/claude/skills/README.md` を参照

## 18.4 検証ループの4つの起動形態

| 形態 | 発火 | 運用上の位置づけ |
|---|---|---|
| standalone | 手動呼び出し | 試運転・単独検証 |
| embedded | 生成系スキルの末尾 | ワークフロー専属チェック |
| chained | スキル終了時に次スキルを呼ぶ | 開発サイクル自律化（習慣を契約に変える） |
| on every PR | CI / Code Review | チームインフラ。チェーン安定後に昇格 |

既存資産との対応: `/design-sync-check`（UI 変更時の chained 先）、
`/safe-auto-merge`（PR ゲートの合流点）、CodeRabbit / Codex review
（AI レビュー層 = PR 形態の一部。`docs/claude` 09・claudeos ai-review 参照）。

## 18.5 スキル化の6ステップ（ブログ準拠）

1. 今週最も頻繁に行った手動チェックを 1 つ選ぶ
2. 組み込みの `/verify` 系スキルで足りるかを先に確認する
3. 新しいチームメイトへ渡すつもりで手順を平易な文章に書き出す
4. `.claude/skills/<name>/SKILL.md` として配置する（skill-creator に生成させてもよい）
5. 新しいタスクで発動させ、チェックが出力に含まれることを確認する
6. 安定したらチェーン化 → さらに安定したら PR ゲートへ昇格する

## 18.6 運用ガードレール

- 修正上限（例: 同一チェック 3 回）で BLOCKED 化し、無限反復によるトークン浪費を防ぐ
  （CLAUDE.md §10 Improvement「改善効果が小さい反復を無制限に続けない」と整合）
- 実行できないチェックは成功扱いにせず NOT RUN / BLOCKED として理由を記載する
- チェーン化はトークン消費を増やすため、広く展開する前に単体試験する
- PR ゲート化はチェーンが安定してから（調整がチーム全体へ波及するため）
- Rubrics in Claude Managed Agents（grader agent による rubric 検証）は
  Managed Agents PoC が sandbox バグでブロック中のため導入対象外
  （`docs/claude/06`・`07` 参照。beta フィードバック回答待ち）

## 18.7 適用判断の記録（Decision Log）

2026-07-24 適用。検出したギャップと対応:

| # | ギャップ | 対応 |
|---|---|---|
| G1 | `.claude/skills/` の flat .md がスキルとして未認識 | ディレクトリ + SKILL.md 形式へ移行し、認識されることを実証 |
| G2 | claudeos `verification-loop` スキルが汎用ガイドのみ | ブログの4形態・6ステップ・ループ規則で改訂（正本・テンプレ両方） |
| G3 | template-sync にスキル配布経路がない | skills 配布ステップを追加（存在しない場合のみ・保護つき） |

対象外とした項目: GitHub Actions への検証ジョブ追加（CI 分数課金 = 別 PR）、
Code Review (research preview) 有効化（課金 = 人間決断）、
Managed Agents Rubrics(前掲)。
